# Nanozyme Extractor — DataCon'26

Система извлечения структурированных данных о **нанозимах** из научных PDF-статей и её сравнение с
бейзлайном бенчмарка [ChemX](https://github.com/ai-chem/ChemX) (NeurIPS 2025).

Домен: **Nanozymes** (наночастицы с ферментоподобной активностью — кинетика и условия реакции).
Постановка задачи целиком — в [`docs/TASK.md`](docs/TASK.md).

## Результат одной строкой

| Что меряем | Значение | Комментарий |
|---|---:|---|
| Бейзлайн ChemX (single-agent), Macro-F1 | **0.164** | планка, которую нужно превзойти |
| Наша метрика воспроизводит бейзлайн | **0.1640** | один-в-один, доказывает корректность измерения |
| **Наша экстракция, full-set** (39 статей) | **0.1830** | **выше планки уже при покрытии 12/39** |
| Наша экстракция, covered-only (12 статей) | **0.5947** | качество на покрытых статьях — ×3.6 от планки |
| Слой сериализации на предсказаниях бейзлайна | **0.2379** | +45% к 0.164 **без единого вызова LLM** |

Главный вывод: **планка 0.164 побита**, причём с большим запасом по качеству. Полный (full-set) балл
сейчас ограничен не качеством модели, а **покрытием PDF** — у нас на руках 12 из 39 open-access статей
(остальные блокируются защитой издателей от ботов).

---

## В чём идея решения

Мы сознательно начали не с экстрактора, а с **измерительного слоя** — и это окупилось.

1. **Сначала метрика, потом модель.** Прежде чем что-то извлекать, мы дословно воспроизвели метрику
   ChemX и убедились, что она даёт ровно их `0.164`. Без честного измерения любые улучшения — вслепую.

2. **Разбор механики метрики — половина успеха.** Метрика ChemX устроена неочевидно (см. раздел
   [«Как считается метрика»](#как-считается-метрика)). Поняв её, мы обнаружили, что **значительная часть
   баллов теряется на форматировании**, а не на содержании. Один только корректный слой сериализации
   поднимает предсказания бейзлайна с `0.164` до `0.238`.

3. **Слой нормализации под конвенции эталона.** Пустые поля, формат чисел, канонические написания
   категориальных значений — всё приводится к тому виду, который ожидает метрика.

4. **Экстрактор на Claude Opus 4.8.** Модель получает статью (PDF целиком или извлечённый текст) и
   возвращает строго типизированный JSON по схеме ChemX (structured output). Поверх — слой нормализации.

5. **Веб-интерфейс на Streamlit** для демонстрации: загрузил PDF → получил таблицу.

Каталог `data/` создаётся при запуске и не коммитится (кроме `data/manual/`):

- `data/pdfs/` — скачанные PDF статей + `manifest.csv` со статусом загрузки;
- `data/txt/` — извлечённый из PDF текст (для текстового режима экстракции);
- `data/manual/` — предсказания по статьям в формате `{"samples": [...]}` (см. раздел про режимы).

## Как считается метрика

Это ключевой для понимания раздел — именно механика метрики определяет стратегию.

Метрика ChemX (`nanozx/metric.py`, воспроизводит `LLM/src/metric_calc.py` из ChemX) работает так:

- **Сравнение по-колоночное, а не по-строчное.** Для каждой статьи и каждого из 20 полей берётся
  *мешок* (мультимножество) значений по всем строкам и сравнивается как мешок: TP — сколько истинных
  значений нашлось среди предсказанных, FP/FN — остаток. Сопоставлять строки между собой **не нужно** —
  важен правильный набор значений в каждой колонке.
- **Совпадение строго точное по строке** (`astype(str)`, посимвольное равенство). `"25"` ≠ `"25.0"`,
  `"H2O2 + TMB"` ≠ `"TMB + H2O2"`.
- **Пустые значения — это тоже значения, которые нужно угадать.** В эталоне пустое **строковое** поле
  имеет вид `NOT_DETECTED`, пустое **числовое** — строку `nan`. Если поля в статье нет и мы корректно
  выдали `NOT_DETECTED`/`nan` — это засчитывается как TP.
- **Числа — это `float64`**, приведённые к строке: целые становятся `25.0`, `1.0`. Поля `length / width /
  depth` хранятся как строки и пишутся «как есть» (`5`, `3.21`).
- Оценка усредняется **по статьям**, затем **по полям** → **Macro-F1**. Считаются только open-access
  статьи (`access == 1`): для Nanozymes это **111 строк в 39 статьях**.

Отсюда два следствия, на которых построено решение:

1. **Корректная сериализация бесплатно поднимает балл.** Бейзлайн пишет `'NOT_DETECTED'` (с кавычками)
   и целые без `.0` — и теряет почти все пустые и «целочисленные» поля на форматировании. Мы это чиним.
2. **Важна правильная мощность строк на статью.** Раз пустышки засчитываются, верное число строк +
   верные `nan`/`NOT_DETECTED` дают много TP на разреженных полях (`syngony`, `surface`, `temperature`).

Запустить доказательство этого тезиса:

```bash
python scripts/prove_serialization.py
# reproduced as-is macro-F1:  0.1640   (= published 0.164)
# format-only macro-F1:       0.2379
```

## Установка

Требуется Python 3.11+.

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env               # и впишите ANTHROPIC_API_KEY для режима api/text
```

Датасет `ai-chem/Nanozymes` подтягивается автоматически с Hugging Face при первом запуске
(`nanozx/dataset.py`) и кэшируется в `data/cache/`.

## Запуск

### 1. Добор PDF статей (по DOI)

```bash
python scripts/download_pdfs.py
```

Качает open-access PDF через Unpaywall и парсинг `citation_pdf_url`, кладёт в `data/pdfs/`,
пишет `data/pdfs/manifest.csv` со статусом по каждой статье. Часть издателей блокирует автоскачивание —
эти PDF добираются вручную/браузером (см. [«Ограничения»](#ограничения-и-дальнейшие-шаги)).

### 2. Экстракция

```bash
# режим API — Claude Opus 4.8 получает PDF целиком (text + vision):
python scripts/run_extract.py --source api

# текстовый режим — отправляется извлечённый из PDF текст
# (дешевле и укладывается в жёсткие rate-limit'ы; кинетика обычно в тексте/таблицах):
python scripts/run_extract.py --source text --sleep 70

# manual — берёт готовые предсказания из data/manual/<pdf>.json
# (полезно для воспроизводимости и оффлайн-прогона без ключа):
python scripts/run_extract.py --source manual
```

Результат всех режимов — единый `data/cache/preds.csv`.

### 3. Подсчёт метрики

```bash
python scripts/score_preds.py
```

Печатает два числа: **full-set Macro-F1** (по всем 39 статьям; непокрытые идут в ноль) и
**covered-only Macro-F1** (только по статьям, для которых есть предсказания) + разбивку по полям.

### 4. Веб-демо

```bash
streamlit run app/streamlit_app.py
```

Загрузка PDF → извлечение через Claude Opus 4.8 → таблица в формате ChemX + выгрузка в CSV.
Требует `ANTHROPIC_API_KEY` в окружении.

## Результаты по полям

Сравнение качества по полям (наш экстрактор, covered-only) с бейзлайном ChemX. Видно, где мы выигрываем
уверенно, а где упирается в объективный потолок (см. ниже).

| Поле | Бейзлайн F1 | Наш F1 | Поле | Бейзлайн F1 | Наш F1 |
|---|---:|---:|---|---:|---:|
| activity | 0.380 | **0.888** | km_value | 0.290 | **0.555** |
| reaction_type | 0.276 | **0.888** | km_unit | 0.270 | **0.534** |
| formula | 0.326 | **0.805** | c_const | 0.122 | **0.732** |
| length | 0.254 | **0.781** | ph | 0.256 | **0.659** |
| width | 0.193 | **0.721** | vmax_unit | 0.139 | 0.400 |
| depth | 0.000 | **0.721** | temperature | 0.000 | 0.446 |
| surface | 0.017 | **0.680** | vmax_value | 0.222 | 0.275 |
| syngony | 0.070 | **0.613** | ccat_value | 0.096 | 0.333 |

Слабый хвост (`vmax_value`, `ccat_value`, единицы измерения) — это точные числа и единицы, которые для
части статей **физически находятся в Supporting Information (ESI)**, а её у нас нет. Плюс сам эталон в
этих полях неконсистентен (например, юникод-минус `−` против дефиса `-` в `M s-1`), что ставит потолок
по точному совпадению.

## Схема домена Nanozymes (20 полей)

| Поле | Тип | Пустое значение | Поле | Тип | Пустое значение |
|---|---|---|---|---|---|
| formula | str | `NOT_DETECTED` | reaction_type | str | `NOT_DETECTED` |
| activity | str | `NOT_DETECTED` | c_min | float | `nan` |
| syngony | str | `NOT_DETECTED` | c_max | float | `nan` |
| length | str-число | `nan` | c_const | float | `nan` |
| width | str-число | `nan` | c_const_unit | str | `NOT_DETECTED` |
| depth | str-число | `nan` | ccat_value | float | `nan` |
| surface | str | `NOT_DETECTED` | ccat_unit | str | `NOT_DETECTED` |
| km_value | float | `nan` | ph | float | `nan` |
| km_unit | str | `NOT_DETECTED` | temperature | float | `nan` |
| vmax_value | float | `nan` | vmax_unit | str | `NOT_DETECTED` |

Поля-источники (`doi`, `pdf`, `title`, ...) в оценке не участвуют.

## Ограничения и дальнейшие шаги

Чтобы не вводить в заблуждение — честный список того, что ещё не закрыто, по убыванию влияния на балл.

1. **Покрытие PDF: 12 из 39.** Это главный ограничитель full-set метрики. Остальные статьи блокируются
   защитой издателей (MDPI, ACS, Elsevier, Wiley, PMC) от автоскачивания. Добор браузером поднимет
   official-балл в разы (full-set ≈ 0.18 → ≈ 0.6 при том же качестве).
2. **Supporting Information (ESI).** Кинетика (`km`, `vmax`, концентрации) у части статей лежит в
   приложениях. Их подмешивание (как `merge_suppl` в ChemX) закрывает слабый числовой хвост.
3. **Нормализация единиц измерения.** Канонизация написаний единиц даст ещё несколько процентов, но
   потолок ограничен неконсистентностью самого эталона.
4. **Rate limits.** Полный прогон через API упирается в лимиты тарифа ключа; для этого добавлен
   экономный текстовый режим с троттлингом.

## Воспроизводимость

- Метрика (`nanozx/metric.py`) дословно повторяет `metric_calc.py` из ChemX и проверяется скриптом
  `prove_serialization.py`, который воспроизводит опубликованный бейзлайн `0.164` до знака.
- Датасет фиксируется кэшем parquet; режим `--source manual` позволяет пересчитать метрику без сети и
  без API-ключа из сохранённых предсказаний `data/manual/`.
- Зависимости зафиксированы в `requirements.txt`.
